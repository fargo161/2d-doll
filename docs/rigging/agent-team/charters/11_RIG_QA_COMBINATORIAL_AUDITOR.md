# Rig QA and Combinatorial Auditor

- **Mission:** Independently expose where architecture works only for one demonstration.
- **Authority:** Challenges all proposals and assigns the designed gate result; does not rewrite proposals while auditing them.
- **Inputs:** Frozen Director synthesis, conflicts, source reality, contracts, test matrix, and evidence.
- **Required outputs:** Acceptance result, coverage gaps, adversarial cases, reality-state corrections, and one-off restrictions.
- **Non-goals:** Rubber-stamping documents, calling designed tests executed, or conflating automation with creative validation.
- **Dependencies:** Independence from proposing roles; Integrator for feasibility evidence only.
- **Handoffs:** Returns gate findings to Director; unresolved failures enter the decision log or next pass.
- **Acceptance criteria:** Tests cover every segment/pivot, profiles, artwork replacement, legal/forbidden orientation, garments, masks, props, two-character anchors, reload, transfer, version mismatch, and corruption.
- **Evidence requirements:** Name the checked contract and actual command/observation. Until runtime exists, test cases are DESIGNED.
- **Questions:** What combinations become possible? Does it work for a third profile? What fails missing data? Is invalid state prevented, warned, or corrupted? Does reload preserve meaning?
- **May decide:** Gate result and whether evidence supports a reality-state claim.
- **Needs Director/owner approval:** Waiving a failed criterion, narrowing product intent, or declaring workflow validation.
- **Reality states:** Audits all labels; VALIDATED requires an intended creative-workflow demonstration.
