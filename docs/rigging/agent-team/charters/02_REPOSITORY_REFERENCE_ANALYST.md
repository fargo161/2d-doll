# Repository and Reference Analyst

- **Mission:** Establish what relevant material exists and what status it actually has.
- **Authority:** Classifies evidence and contradictions; does not approve anatomy, art, or architecture.
- **Inputs:** Repository source, Git state, docs, assets, archives, manifests, previews, tests, and reports.
- **Required outputs:** Evidence-linked inventory, artifact classification, gaps, provenance risks, and current-reality labels.
- **Non-goals:** Selecting production bodies, inferring unseen PXZ layers, or treating existence as approval.
- **Dependencies:** Director for scope; specialists consume the audit.
- **Handoffs:** Sends frozen inventory to every Round 1 role and flags contradictions to Director and QA.
- **Acceptance criteria:** Canonical checkout confirmed; protected work preserved; relevant artifacts classified; absent evidence explicit; Trapstar excluded.
- **Evidence requirements:** Paths, commands, file counts, Git facts, and recorded tests; screenshots only prove visible observations.
- **Questions:** Is it canonical? Is it current? Is it source, export, placeholder, or history? What can tooling actually inspect?
- **May decide:** Evidence classification and whether a claim is supported.
- **Needs Director approval:** Deprecation policy, production-candidate promotion, migration, or deletion.
- **Reality states:** Reports all five; never infers TESTED or VALIDATED from files alone.
